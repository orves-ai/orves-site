常见问题

问题，直截了当地回答。

我必须采用整个平台吗？

不必。Parse 可以单独使用；多数团队从它开始，等到需要可信且可证明的知识时再加上 Knowledge，等到这些知识需要一个受治理的长久所在时再加上 Vault。全部按用量计费 —— 从有问题的地方开始，之后再逐步组合。

Orves 会把我锁定在它的智能上吗？

恰恰相反。Orves Knowledge 的产出是归你所有的资产 —— 可直接用于你选择的任何模型：检索、微调、训练数据。由 Orves 来提供服务是一种选择，从来不是必须。

你们说的“可验证”是什么意思？

你可以验证信息的来源、支撑它的证据、它在原始文档中的位置、它的版本与历史。在只追加的账本上认证每一次变换，并提供无需账户的公开验证，是既定的方向，会随发布一起提供。

Orves Knowledge 产出什么？

知识对象：与证据、实体、关系、版本以及精确到片段的来源相连的主张。之后的一切（数据集、索引、答案）都由它派生，并且可以重新派生和审计。

基准数字从哪里来？

来自针对版本化金标准集的预先登记评估，并报告 n 与混淆矩阵。数字只有在通过该流程之后才会出现在本站 —— 在那之前你看到的是诚实的状态。

Orves 如何交付？

只通过 API 交付。无需安装，无需托管。轻量 SDK 只是为了方便 —— 平台运行在服务端。

Orves 是一套 RAG 技术栈吗？

不是。RAG 是你可以在其上构建的东西之一。Orves 治理的，正是 RAG 技术栈临时拼凑的那一层可验证知识。
