取り込みエンジン · parse · パイロット

非構造のまま入って、構造化データとして出る。

Orves Parse は、認証された API 呼び出し一つで、複雑な文書を構造化され出典に結びついたデータに変換します。設計から非同期です。文書を送信し、ジョブを問い合わせ、結果を取得します。単体で使える API で、プライベートパイロット中です。最終目的地ではなく、最初の層です。

構築を始める 料金を見る
PDF · パイロット中非同期ジョブ構造を保持再現可能
POST /v1/parse
# submit a document (multipart)
POST /v1/parse  file=@contract_2024.pdf

# 202 Accepted
{ "id": "prs_9f2c41…", "object": "parse",
  "status": "queued" }

# poll until completed
GET /v1/parses/prs_9f2c41…
{ "status": "completed",
  "result": { "json_url": "…/result" } }
課題

AI システムが嘘をつき始めるのは、パースの段階です。

多くのパーサーは文書を一本の文字列に押しつぶします。構造、幾何、表、来歴は、どのモデルが内容を見るより前に壊されます — そしてその後のどの工程も、パースが失ったものを取り戻せません。

押しつぶされた表失われた読み順孤立した脚注出典スパンがない静かな読み取りエラー
ふつうの結果文書→「一本の長い文字列」→LLM→自信たっぷりで、間違い
Parse なら文書→成果物 + スパン→LLM→根拠づけられ、確認できる

設計から出典に結びつく

  • 来歴
  • バージョン管理
  • ロードマップ

出力は、それを生んだ文書に結びついたままです。型付き要素、座標、証明書は公開された方向であり、提供が始まってはじめて告知されます。

見てみる

API が返すそのままの、一つのレスポンス。

左: ページ。右: 受け取るもの — 文書の構造をきれいで構造化された Markdown として保持したもの。

GET /v1/parses/{id}/result
# 200 OK
{ "markdown": "# Q2 Report\n\n## Revenue by segment\n\n| Segment | Q2 |\n| --- | --- |\n| Cloud | 104.2 |\n| Devices | 61.8 |\n\nRenewal is scheduled for…" }

稼働中のパイロット契約からのレスポンスです。幾何と座標を伴う型付きの構造要素は公開された方向であり、提供開始時に告知します。それより前に告知することはありません。

Benchmarks

主張の前に、測定を。

測定するもの: 読み順、表構造、テキスト精度、フォーム項目、長文文書の忠実度 — そして図表。図表ではパースは推測せずに棄権します。

公開される結果は、事前登録された評価を経た後にのみ出されます — それまでこのサイトに数値は現れません。ベンチマークの方法 →
