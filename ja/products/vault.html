永続的な知識 · vault · 開発中

残す価値のある知識には、居場所がふさわしい。

Orves Vault は、組織が生み出す、あるいは取り込む知識 — 文書、Parse の出力、ナレッジオブジェクトとそのグラフ — を保管し、整理し、統制し、Web・API・SDK・MCP を通じて人・アプリケーション・モデル・エージェントに提供します。開発中です。このページは Vault が何をするために作られているかを説明しています。

課題

パイプラインの中に住む知識は、蒸発します。

パースされた文書、抽出された事実、苦労して得た文脈は、バケット、ベクトルストア、ノートブックに散らばって終わります — バージョンも統制もなく、次にそれを必要とするシステムからは見えません。ストレージはファイルを保ちます。知識は保ちません。

散らばった出力権限がない履歴がない監査証跡がない一つのスタックに縛られる
Vault がある理由

Prove が生み、Vault が守る。

Parse が情報源を構造化します。Prove は届いた証跡を読み、現在の Vault の状態と比較し、追跡可能な主張・関係・変更案を生み出します。Vault はその結果として生じた知識の状態を確定し、バージョン管理し、証跡・履歴・相違とともに保持します。

Orves Prove — 変換

  • 届いた証跡を読む
  • 現在の Vault の状態と比較する
  • 主張、実体、関係を生み出す
  • 提案するすべての主張と関係を証跡に根拠づける

Prove の実行ごとに、追跡可能な結果が生まれます。

Orves Vault — 状態

  • 提案された変更を新しいバージョンとして確定する
  • 証跡、履歴、相違を保持する
  • 誰が何を見て変更できるかを統制する
  • 現在の状態を、その履歴とともに提供する

Vault はその結果を、実行をまたいで、時間をまたいで保持します。

積み重ねのループ
新しい情報源→Parse→Prove が現在の Vault の状態を読む→届いた証跡を比較する→追加 · 確認 · 精緻化 · 更新 · 反証 を提案する→Vault が新しいバージョンを確定する

現在の状態、証跡、履歴はいつでも参照できます — 何も闇雲に追記されず、何も静かに上書きされません。

相違を、保持する

矛盾は誤りではなく、知識です。

二つの機関が同じ指標を予測し、見解が分かれます。Prove は二つの主張を関係づけ、Vault は両方を — 著者、日付、証跡とともに — 保持します。平均を取ることも、片方を上書きすることも、合意を作り出すこともしません。

関係の語彙

後から来た情報源は、以前の立場を更新することも、別の機関に反証することも、先行する主張を精緻化することも、同じ主題について無関係な見方を持ち込むこともあります。Prove が関係を提案し、Vault がその区別を保持します — 静かな統合は決してしません。

vault の内側

証跡に裏づけられたナレッジグラフ

実体と主張は、意味が似ているから結ばれるのではありません。すべての関係が、来歴、出典参照、時間的文脈、そしてそれを生んだ証跡を保持します。

アクセスと統制 · 開発中

人、アプリケーション、モデル、エージェントへ提供。

Vault は Web・REST API・SDK・MCP を通じて知識を提供するために作られています。検索は、関連する主張を、その証跡、対立する見解、履歴とともに、一つの追跡可能なレスポンスで返すよう設計されています。ばらばらのチャンクではなく、単一の AI 提供者に縛られることもありません。

Vault は知識を提供します。知能を提供するのは、お客様のアプリケーションとモデルです。

統制

組織ごとの分離、vault と情報源のレベルでの権限、完全な履歴と監査。各制御は提供が始まったときに告知します — それより前に告知することはありません。

ユースケース

精査に耐えなければならない知識のために。

機関リサーチ

レポート、電話会議、音声、データセットをまたいで、予測・見解・修正・出典証跡を維持します。

法務とコンプライアンス

主張、条項、先例、証跡を、元の出典までたどれる状態に保ちます。

企業ナレッジ

ポリシー、文書、社内システムを、所有権・来歴・履歴を失わずにつなぎます。

AI とエージェント

API または MCP を通じて、モデルに永続的で権限を意識した、証跡に裏づけられた文脈を与えます。

製品ではなく、性質

すべての成果物が検証可能です。

認証は Orves が生み出すすべてを貫いています。検証は公開され、再現でき、Orves のアカウントに依存しないように設計されています。
